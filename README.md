# depviz

Инструмент визуализации графа зависимостей пакетов Python (формат pip).
Практическая работа №2 «Конфигурационное управление», вариант 1.

Зависимости получаются напрямую из JSON-описания пакета в репозитории
(PyPI), без `pip` и сторонних библиотек: используется только стандартная
библиотека Python 3.9+.

## 1. Общее описание

Программа по имени пакета:

1. скачивает список его прямых зависимостей (`requires_dist`);
2. строит граф транзитивных зависимостей обходом в глубину (DFS) без
   рекурсии с ограничением по глубине, корректно обрабатывая циклы;
3. выводит граф и найденные циклы, при желании — ASCII-дерево;
4. умеет выводить обратные зависимости (кто зависит от пакета);
5. сохраняет граф в виде текста на языке D2 и изображения SVG.

Структура репозитория:

```
src/depviz/    исходный код
tests/         модульные тесты (unittest)
examples/      тестовые репозитории (графы из заглавных букв)
run.sh         запуск программы
run_tests.sh   запуск тестов
```

## 2. Функции и настройки

### Параметры командной строки

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория | `https://pypi.org/pypi` |
| `-t`, `--test-mode` | режим тестового репозитория: `--repo` — путь к файлу | выключен |
| `-o`, `--output` | имя файла с изображением графа (`.svg`) | `graph.svg` |
| `-a`, `--ascii-tree` | вывести зависимости в виде ASCII-дерева | выключен |
| `-d`, `--max-depth` | максимальная глубина анализа, 0..100 | `3` |
| `-R`, `--reverse` | вывести обратные зависимости | выключен |
| `-c`, `--candidates` | пакеты pip (через запятую), среди которых искать зависимые | — |

Все параметры проверяются: неверное имя пакета, недопустимый URL,
отсутствующий файл тестового репозитория, глубина вне диапазона, имя
выходного файла не `.svg` или несуществующий каталог — это ошибки с
понятным сообщением `error: ...` и кодом возврата 1.

### Как строится граф

- Репозиторий должен отдавать описание пакета по адресу
  `<repo>/<package>/json` (формат PyPI JSON API). Берётся последняя версия.
- Имена пакетов приводятся к каноническому виду (PEP 503).
- Необязательные зависимости (`extra == ...`) пропускаются.
- Узлы глубже `--max-depth` остаются листьями. Если узел достигнут
  более коротким путём, он раскрывается заново, поэтому лимит глубины
  не скрывает узлы, достижимые в его пределах.
- Циклические зависимости не приводят к зацикливанию. Найденные циклы
  выводятся списком, в дереве они помечаются `(cycle)`, а повторно
  встреченные поддеревья — `(*)`.

### Обратные зависимости

С `--reverse` рёбра графа переворачиваются, и тем же обходом ищутся
пакеты, которые зависят от заданного. В тестовом репозитории
просматривается весь файл. У репозитория pip нет индекса зависимых
пакетов, поэтому в режиме URL они ищутся среди пакетов из `--candidates`.

### Тестовый репозиторий

Текстовый файл, пакеты названы заглавными латинскими буквами. Строка
`A: B C` означает «A зависит от B и C»; пустые строки и строки,
начинающиеся с `#`, игнорируются; пакет без строки не имеет зависимостей.
Примеры: `examples/diamond.txt`, `examples/cycle.txt`,
`examples/chain.txt`, `examples/shared.txt`.

### Изображение графа

Рядом с изображением сохраняется текст на языке D2 (`graph.svg` →
`graph.d2`). Если в системе установлена программа
[d2](https://d2lang.com), SVG строится ею. Иначе используется встроенная
простая послойная раскладка: корень сверху, стрелки идут к зависимостям,
обратные рёбра (циклы) изгибаются вправо.

## 3. Сборка и тесты

Сборка не нужна. Требуется Python 3.9 или новее.

```
./run_tests.sh
```

Эквивалентная команда: `PYTHONPATH=src python -m unittest discover -s tests -v`.
Запуск: `./run.sh --help`.

## 4. Примеры использования

### Реальный репозиторий

```
./run.sh -p requests -d 2 -a -o requests.svg
./run.sh -R -p idna -c requests,flask
```

### Ошибки

```
$ ./run.sh -p "bad name"
error: invalid package name 'bad name': need a pip name
$ ./run.sh -p requests -d 500
error: max depth must be in range 0..100
$ ./run.sh -p requests -r ftp://x
error: invalid repository URL: 'ftp://x'
$ ./run.sh -p requests -o a.png
error: output file must have .svg extension
$ ./run.sh -t -r examples/chain.txt -p Z
error: package Z is not in test repository
```

### Ромб без циклов (`examples/diamond.txt`)

```
$ ./run.sh -t -r examples/diamond.txt -p A -d 5 -a -o diamond.svg
Dependencies of A (max depth 5):
A -> B, C
B -> D
D -> (none)
C -> D
Dependency tree:
A
|-- B
|   `-- D
`-- C
    `-- D
D2 source saved to diamond.d2
SVG image saved to diamond.svg (renderer: built-in)
```

### Цикл (`examples/cycle.txt`)

```
$ ./run.sh -t -r examples/cycle.txt -p A -d 10 -a -o cycle.svg
Dependencies of A (max depth 10):
A -> B
B -> C
C -> A, D
D -> (none)
Cyclic dependencies:
  A -> B -> C -> A
Dependency tree:
A
`-- B
    `-- C
        |-- A (cycle)
        `-- D
```

### Ограничение глубины (`examples/chain.txt`)

```
$ ./run.sh -t -r examples/chain.txt -p A -d 2 -o chain.svg
Dependencies of A (max depth 2):
A -> B
B -> C
C -> (none)
```

Узел `C` лежит на предельной глубине, поэтому показан без зависимостей.

### Обратные зависимости (`examples/shared.txt`)

```
$ ./run.sh -t -R -r examples/shared.txt -p E -d 5 -o rev.svg
Reverse dependencies of E (max depth 5):
E -> B, C
B -> A
A -> G
G -> D, E
D -> B
C -> A
Cyclic dependencies:
  B -> A -> G -> D -> B
  E -> B -> A -> G -> E
```

Текст D2 для этого графа (`rev.d2`):

```
direction: down
E
B
A
G
D
C
E -> B
E -> C
B -> A
A -> G
G -> D
G -> E
D -> B
C -> A
```

## 5. Сравнение со штатными инструментами pip

Для сравнения с результатом программы можно использовать:

```
pip show requests
pip install --dry-run --ignore-installed --report - requests
pip install pipdeptree && pipdeptree -p requests
```

`pip show` перечисляет прямые зависимости установленной версии,
`pip install --dry-run --report` — полный набор пакетов, которые pip
установит, `pipdeptree` рисует дерево по установленным пакетам.

Расхождения с `depviz` возможны по следующим причинам:

- `depviz` читает последнюю версию пакета с PyPI, а `pip show` и
  `pipdeptree` — установленную в окружении;
- `depviz` не вычисляет маркеры окружения (`python_version`,
  `platform_system`): зависимость с маркером попадёт в граф, даже если
  pip не установит её на текущей платформе;
- необязательные зависимости (`extra`) пропускаются, ограничения версий не
  учитываются, поэтому `depviz` не разрешает конфликты версий, как это
  делает pip;
- `depviz` строит граф до глубины `--max-depth`, а штатные инструменты
  показывают его полностью.
